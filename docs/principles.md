# Principles

What VibeForge does and won't do. A change that breaks one of these needs a reason in its pull request, and a decision from the maintainer.

## It runs the CLIs you already sign in to

VibeForge never calls a cloud model API and never holds a cloud API key. Every cloud engine is a coding CLI on your `PATH` that you signed in to yourself; VibeForge starts it in a real terminal and gives it a home. If a CLI isn't signed in, its terminal shows the CLI's own sign-in. Viby plans with one of those CLIs, on that CLI's own subscription, in a turn that can't change anything. When you explicitly opt in to **Settings → Local AI**, VibeForge can also point an installed coding CLI (OpenCode, Claude Code, or Codex) per spawn at your own keyless local or home-network server without modifying your saved CLI configs, and Viby can talk directly to that server's OpenAI-compatible chat endpoint. Where Viby plans is its own setting (**Viby in Local mode**: Cloud or a local model), so turning Local mode on moves your coding tools without moving Viby unless you chose that. It is told what Viby shows you: your workspaces, CLIs, agents, tasks, routines, and what's running or waiting for review, and with each request the view, workspace and terminal in front of you. When it needs to inspect or summarise work for you, it reads a CLI's answer, terminal screen or diff from this machine through that same planning CLI. Past runs and folder names go to it only when you ask it to find something, and folder names only from where projects are kept (your projects folder and `~/Projects`). A screenshot of the screen goes to it only when you turned on **Settings → Computer use** and allowed Viby to see that place: VibeForge's window, the browser in Code, or the desktop.

Plan limits, when you turn them on, read the sign-in a CLI saved on this machine to ask its provider for your usage. VibeForge never renews, rewrites or keeps that sign-in, and saves only the percentages.

## No telemetry

VibeForge sends no analytics, crash reports or usage data anywhere. Its own log (`~/.local/share/vibeforge/logs/vibeforge.log`) stays on this machine and never holds prompts or terminal output. **Help → Copy diagnostics** and the bug report form are things you send yourself, after reading them.

## Your files are plain text

Agents, briefs, memory, skills, routines and tasks, and Viby's own memory (`viby.md`), are YAML and Markdown under `~/.config/vibeforge`; engines, settings and workspaces are JSON beside them. Edit them in any editor and VibeForge picks up the change. Each run is a folder under `~/.local/share/vibeforge/runs` holding its prompt, transcript, final screen and diff (the long files gzipped once it ends).

## Networked features are opt-in

Anything that goes over the network stays off until you turn it on:

- **Plan limits** (Settings → Usage and activity) ask Anthropic, xAI, Google, Moonshot, OpenAI and Meta, at most every 3 minutes.
- **The GitHub graph** (Settings → Usage and activity → GitHub) asks GitHub through your `gh`, at most every 30 minutes, and keeps no token.
- **The phone page** (Settings → Phone) listens on `127.0.0.1:4737` only, behind a pairing code; Tailscale Serve is how a phone reaches it, and you turn that on yourself. Settings only asks this computer's own `tailscale` where things stand. A phone that shows two of your computers asks each one directly, with that computer's own code; a computer answers a page from another machine on the same tailnet and, opened on this computer itself, a page from another local port (where the phone page is tried out), and no other. Every request needs a key: pairing with the code gives each phone a key of its own, and VibeForge keeps only a hash of it. Requests that come through Tailscale Funnel, which would put the page on the internet, are refused.
- **Sync** (Settings → Sync) starts a private Syncthing that listens on port 22737 and announces itself on the local network only. It talks to the machines you paired and to nothing else: no discovery servers, relays, usage or crash reports, or upgrades. Only workspaces you pick are synced.
- Speech models and Piper voices download from Hugging Face, and sherpa-onnx (which runs Parakeet, Canary and Moonshine) from its GitHub release, only when you press Download or say go to a download Viby planned.
- **Local AI** (Settings → Local AI) stays off until you enable it and connects only to loopback (`127.0.0.1` / `localhost`) or the home-network / Tailscale address you enter — never third-party cloud APIs. **Run a server** starts only the program you set up there (`llama-server`, `ollama serve`, `lms server start` or your own command), bound to `127.0.0.1` unless your own options say otherwise, and ends it when you press Stop, switch back to Cloud with **Start with Local mode** on, or quit. VibeForge downloads no models and installs no services.

**The update check is the one networked call that is on by default** (`checkUpdates` in `src/core/store/config.ts`). Twenty seconds after start and every six hours, VibeForge asks GitHub's release API for the newest release number. The request carries nothing but your IP address and `VibeForge/<version>` as its user agent. **Update** then downloads that release's `install.sh` from GitHub and runs it only if it matches the SHA-256 GitHub lists for it. Turn it off in **Settings → Updates** (or set `"checkUpdates": false` in `settings.json`); **Check now** still works.

## A person decides each step

- Writing or assigning a task starts nothing. **Execute** does.
- Viby asks before acting at the level you choose in **Settings → Viby**: **Ask for everything** (every plan is a card that waits for **Go**), **Ask only for risky actions** (the default), or **Never ask** (nothing waits; your call). Under **Ask only for risky actions**, anything risky waits for **Go**: deleting, clearing or replacing an agent's memory or Viby's, stopping, applying or discarding, tidying runs, a shell command other than tests, a build, reading git or making folders, <kbd>Ctrl</kbd>+<kbd>C</kbd>, answering a CLI that asks to run a command or make an edit, a download, adding or removing a CLI, starting tasks a CLI handed out, or a setting that turns something networked on, lets a CLI do more on its own, or keeps runs for less time. So does anything that gives an agent, a skill or a CLI more to act on: a new agent, or one given more folders, another CLI, a new brief, skills or memory; a skill made or changed; a routine made, changed or turned on; a task made and started at once; a message sent in a chat or a run continued with new words; a note added to Viby's memory; a slash command typed into a CLI; and agent talk turned on, given a lead or allowed more than now. And once Viby has read a screen, a file, a diff or a reply to make a plan, only steps that just look go without **Go**, with one exception: clicking, scrolling and focusing a window on a place you allowed, and typing or shortcuts that come from your own words. What Viby reads tells it where things are, never what to do: text it would type, or a Ctrl/Alt/Super shortcut, that came from the screen waits for **Go**. A plan that only shows you something (a workspace, a view, a terminal, a page on this computer) or reads a CLI's answer out goes at once: it changes nothing. A page from another site waits for **Go**, as its address could carry what Viby was shown. When a check Viby runs in its own copy fails, the failure goes back to the CLI working in that copy, a set number of times; the copy still comes back only through **Apply**.
- Dictated words land in the box or terminal and wait for you to press Enter.
- Viby's computer use is off until you turn it on in **Settings → Computer use**, where each place (VibeForge's window, the browser in Code, the desktop) has its own switches for seeing it, clicking and scrolling in it, and typing in it. Only you change them: Viby's own settings steps can't reach them. Each action is checked against them when it runs, not when it was planned, in every approval mode, **Never ask** included. Under **Ask for everything** every click, scroll or key waits for **Go**.
- A call with Viby is the one place speech sends itself: you start it on purpose, the rail shows it for as long as the microphone is open, and what you say reaches only Viby, never a terminal. In a call, the approval level you chose applies as it does when typing, and a spoken "go" is your **Go**. When Viby speaks up by itself in a call (a CLI ended its turn), it only tells you; nothing is started by it.
- Work done in a task's or Viby's own copy comes back only when you press **Apply**, as uncommitted edits you can read before you commit — or, when the copy has clean commits that were already merged into the workspace's upstream branch (a PR merged on GitHub), by fast-forwarding your branch to that upstream instead of pasting duplicate edits. Checking the upstream branch runs only when you press **Apply** on a copy with clean commits, never in the background.
- A task one CLI hands another waits for you under **Ask first**, the default. So does the first message between two CLIs working in different workspaces: it waits in the receiving CLI's prompt until you send it. Two CLIs can trade 8 messages before the next one waits in the prompt for you.

## Undo instead of "are you sure?"

Deleting an agent, chat, task, skill or routine, discarding a copy, or removing a workspace from VibeForge happens at once, with **Undo** on the toast and <kbd>Ctrl</kbd>+<kbd>Z</kbd>. VibeForge asks first only when something still running would be stopped, or work would be lost for good. A task that finds its folder busy waits its turn and starts on its own, instead of refusing.

## One engine per agent

An agent has one engine. VibeForge doesn't route work between models, pick a cheaper one, or fall back to another when a CLI fails or hits its limit. Viby never starts a CLI you didn't configure (using the CLI or saved Agent you named, or your default CLI setting when none is named), and a lead CLI that hands out tasks decides that itself. The one exception is the explicit **Also switch saved Agents to Local** toggle under **Settings → Local AI**, which runs saved Agents against your configured Local AI server while Local mode is on without altering their `agent.yaml` files on disk. Forks that want routing are welcome.

## Voice stays on this machine

[whisper.cpp](https://github.com/ggml-org/whisper.cpp), or sherpa-onnx for Parakeet, Canary and Moonshine, turns speech into text and [Piper](https://github.com/OHF-Voice/piper1-gpl) speaks Viby's replies, both locally. Viby is the only voice: coding CLIs don't speak. In a call, the Silero model that tells speech from other sound comes with VibeForge and runs here too, and echo is cancelled by this machine's own PipeWire. No audio is sent to a service or kept. The phone's mic records on the phone and sends the audio over your tailnet to this computer's speech model, and nowhere else.

## Honest limits

Allowed folders are a policy, not a sandbox: runs start inside them and the prompt tells the CLI to stay there, but a coding CLI has a shell. A first prompt handed to a CLI on its command line (`promptArgs`) can be read by any other user account on the same computer, through `ps` or `/proc`, for as long as that CLI runs: VibeForge assumes a desktop with one person on it. It is built for Omarchy (Arch + Hyprland) and has no Windows or macOS builds.
